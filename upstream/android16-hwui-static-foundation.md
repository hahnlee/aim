# Android 16 HWUI static Darwin foundation

This gate compiles the pinned Android HWUI source set with the real AOSP
`renderthread/RenderThread.cpp` and GPU pipeline, plus the narrow Darwin host
implementations needed below Android's platform boundary. It contains 87
source translation units and the one `HWUIProperties.sysprop.cpp` translation
unit generated by upstream `sysprop_cpp`, for 88 archive members. It is not a
symbol-pruned archive and it does not provide per-symbol replacements.

## Sparse, Gitless inputs

Keep `_aosp/frameworks/base/libs/hwui` at frameworks/base commit
`99b01a65cc4c104933788b3143285ab6bae65827`. Additional headers should be
materialized as Gitiles subtree archives, without Git metadata:

- frameworks/native commit `2827a4a16b0340ecd07c2d5a6c89991799b362bb`:
  `libs/gui/include`, `libs/binder/include`, and `libs/nativedisplay/include`.
- hardware/libhardware commit `cd2b68d71a1dd9a45668ddd9a507000ccd7ff114`:
  `include_all` (and `include` only when the Soong-compatible symlink facade is
  required). `include_all/hardware/hardware.h` is checksum-locked.
- system/tools/sysprop commit
  `5612a6cb5b56b654f6cd4f1c955606b732a62710`: only root `Android.bp`,
  `sysprop.proto`, `Common.cpp`, `CodeWriter.cpp`, `CppGen.cpp`, `CppMain.cpp`,
  and `include/{Common,CodeWriter,CppGen}.h` are needed to build `sysprop_cpp`.
  Tests and the rest of the project are not needed.

Point `AIM_ANDROID16_SYSPROP_CPP` at the executable built from that
source and `AIM_ANDROID16_SYSPROP_ROOT` at the sparse source root. The
gate verifies the source provenance, invokes:

```text
sysprop_cpp --header-dir <tmp>/include --source-dir <tmp>/source \
  --include-name HWUIProperties.sysprop.h --public-header-dir <tmp>/public \
  HWUIProperties.sysprop
```

and verifies both generated byte hashes before compiling them. A checked-in
handwritten replacement is intentionally not accepted.

`tools/sync-android16-hwui-static-deps.sh` performs this sparse Gitless
materialization and builds the pinned generator using the already gated AOSP
libbase plus the local protobuf toolchain. The build gate invokes it
automatically when dependency overrides are not supplied.

The optional header roots are passed through
`AIM_ANDROID16_{GUI,BINDER,NATIVEDISPLAY,LIBHARDWARE}_INCLUDE` so these
small Gitless trees do not need to be copied into the main `_aosp` materialized
tree.

## Build and acceptance boundary

Run `tools/build-android16-hwui-static-foundation.sh`. The gate verifies the
Android.bp source manifest, compiles all 88 objects for Mach-O arm64 with the
real EGL/GLES RenderThread path, `-fno-rtti`, and the pinned framework Skia
configuration, then validates archive membership and representative HWUI
definitions. `HWUI_NULL_GPU` is deliberately absent: `DeviceInfo` receives the
actual maximum render-target size from the Ganesh context created by
`RenderThread::requireGlContext()`. The existing
`tools/compile-android16-hwui-canvas-gate.sh` remains the executable
`AIM_ANDROID_CRITICAL_JNI_ABI` check for Canvas/Paint JNI; this archive
does not contain those JNI translation units, but pins the patch so the ABI
contract cannot silently drift.

The five common `android_graphics_apex` TUs are emitted as the separate
`libandroid-graphics-apex-common-darwin.a`. They must be linked beside the
88-member core/host archive. Keeping this boundary avoids duplicating the
separately built GraphicsJNI archive. `apex/LayoutlibLoader.cpp` is a host-only
layoutlib loader and is intentionally outside the APEX-common archive.

The full force-load executable is deliberately the next acceptance gate. With
all 88 HWUI objects and all current foundation archives force-loaded, the exact
remaining module closure observed on Darwin is:

- frameworks/base `libs/hostgraphics` (`ADisplay.cpp`, `ANativeWindow.cpp`,
  `Fence.cpp`, `HostBufferQueue.cpp`, `PublicFormat.cpp`) for 13
  `ADisplay_*`/`ANativeWindow_*` definitions;
- upstream Skia `src/ports/SkFontMgr_custom_empty.cpp` and
  `tools/SkSharingProc.cpp`, which are members of Android.bp `libskia` but were
  omitted by the current `_build/skia-text` GN feature selection;
- a corrected framework/Freetype Skia archive. Force-loading the current
  `_build/skia-text/libskia.a` exposes CoreText imports specifically from
  `libskia.SkCTFont.o` and `libskia.SkCTFontCreateExactCopy.o` (including
  `CTFontCreateWithFontDescriptor`, `CTFontDrawGlyphs`, and related constants).
  Adding CoreText would make that diagnostic link pass, but is not accepted by
  this AOSP FreeType gate; the follow-up must correct the Skia module source
  selection so those Darwin-CoreText objects are not in the whole-static
  closure.

Those are module sources/frameworks, not stubs. They are revision-locked here
for the follow-up force-load gate.
